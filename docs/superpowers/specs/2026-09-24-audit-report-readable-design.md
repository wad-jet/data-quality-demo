# Дизайн: человекочитаемый audit-отчёт (MD/HTML)

Дата: 2026-09-24. Статус: проект (для spec review и аппрува).
Исход: spike по задаче «сделать отчёт более человекочитаемым и информативным
для неподготовленного читателя»; прототип утверждён пользователем
(`/tmp/report-after.md`, в репо не входит).

## 1. Цель

Рендеры `md` и `html` от `audit-report.json` (`-from … -format md|html`)
становятся отчётом **на русском** для человека, не погружённого в детали:
с вердиктом в шапке, пояснениями метрик, легендой дефектов, человеческим
таймлайном и чеклистом самопроверки. Текущие рендеры — сырые таблицы с
терминами и unix-временем (см. spike-разбор).

## 2. Scope

**В scope:**
- `RenderMarkdown` и `RenderHTML` (`internal/audit/render.go`) — новая
  структура и язык (русский), по §4.
- Новый файл `internal/audit/explain.go` — русская легенда дефектов,
  статические пояснения метрик, функция вердикта, группировка таймлайна
  (чистые функции, без I/O).
- Тесты: `internal/audit/explain_test.go` (новый), дополнения
  `internal/audit/render_test.go`.
- Доки: `README.md` (секция «Аудит»: md/html — русские «человеческие»
  отчёты), `manual_docs/reference/audit.md` (секция «Форматы отчёта»).

**Non-goals:**
- `text`-формат (stdout, `RenderHuman`) — **не меняется** (для специалистов).
- JSON-схема — **не меняется** (все нужные данные уже есть: `overall`,
  `per_tag`, `dlq`, `dlq_topic`, `timeline`, `ledger_entries`, `warnings`).
- CLI-флаги — не меняются; отдельного флага «объясни» нет — пояснения
  всегда в md/html.
- JS/интерактивность в HTML; английский вариант md/html; CSV.

## 3. Вердикт (детерминированные правила)

Функция `Verdict(r Report) (healthy bool, problems []string)` в `explain.go`:

1. По каждому `per_tag`: `TotalDefects > 0 && Caught < TotalDefects` →
   проблема «не все дефекты вида `<tag>` найдены: caught/total = N/M».
2. Если `DLQTopic != nil && DLQTopic.Count != DLQ.Count` → проблема
   «DLQ: ожидается N, фактически M (расхождение)».
   `DLQTopic == nil` — проблема НЕ ставится (нет факта для сверки).
3. Каждый элемент `Warnings` добавляется списком проблем.
4. `healthy = len(problems) == 0`.

Шапка: healthy → «**Вердикт: прогон здоров.**» + одна фраза-обоснование
(все заложенные дефекты найдены; DLQ сверено — совпадает, если `DLQTopic`
есть). Не healthy → «**Вердикт: обнаружены проблемы (N).**» + маркированный
список проблем.

## 4. Структура отчёта (md и html — один и тот же порядок секций)

1. **Заголовок** «Отчёт о качестве данных (audit)» + блок вердикта (§3).
2. **Что проверяли** — один абзац: «Producer отправил `<ledger_entries>`
   событий, из них заложили дефектов: `<overall.total_defects>`. Инспектор
   нашёл `<overall.findings>` записей: `<overall.caught>` — реальные дефекты,
   `<overall.false_positives>` — ложные срабатывания».
3. **Метрики простыми словами** — таблица 2 строки: Recall (значение
   `caught/total_defects (X%)` + «Доля заложенных дефектов, которые нашли»)
   и Precision (значение `caught/findings (X%)` + «Доля находок, которые
   правда; остальные — ложные срабатывания»).
4. **Дефекты по видам** — таблица: Дефект (тег) | Что это (легенда §5) |
   Заложили | Поймали | Recall | Записей | Ложных | Precision. После
   таблицы: если у `ooo` `false_positives > 0` — пояснительный абзац
   (лаг-событие выглядит и как «не по порядку» — одна причина, две записи;
   это поведение демо, не поломка).
5. **DLQ — «коробка возвратов»** — «Должно быть: N (по журналу)» /
   «Фактически: M (прочитано из брокера)» / статус «совпадает» или
   «РАСХОЖДЕНИЕ» (в HTML — красный маркер). Если `DLQTopic == nil` —
   строка «Фактически: не считалось (нужен поднятый брокер и флаг
   `-dlq-topic`)».
6. **Таймлайн** — группы (кластеры) вместо списка unix-секунд:
   - кластер = последовательные баки `timeline`, разрыв между
     соседними `bucket_s` > 60с → новый кластер;
   - строка кластера: `<HH:MM:SS>–<HH:MM:SS> (время события) [бар] <сумма>`;
     время — UTC (по `bucket_s`), бар — ASCII `█`, ширина пропорциональна
     сумме кластера (макс. кластер = 40 символов);
   - между кластерами — пометка «разрыв Ns — как правило, дефект "лаг":
     события с "старой" отметкой времени».
   - Пустой `timeline` → секция пропускается.
   - HTML: те же кластеры горизонтальными цветными полосами (div + width).
7. **Чеклист «Как проверять отчёт за 10 секунд»** — 4 пункта (recall 100%
   по всем видам; DLQ «совпадает»; precision у ooo/lag может быть < 100% —
   нормально; вердикт в шапке).
8. **Подвал** — «Сгенерировано: <generated_at, UTC> · Данные:
   <inputs.ledger>, <inputs.findings>» + сноска: машиночитаемая версия —
   `audit-report.json`, формат специалистов — `-format text`.

## 5. Легенда дефектов (статика, `explain.go`)

| Тег | Что это |
|---|---|
| `missing` | заказ без обязательного поля |
| `dup` | повторная отправка одного заказа |
| `typedrift` | поле другого типа (число стало текстом и т.п.) |
| `ooo` | события пришли не по порядку |
| `lag` | «старое» событие (отметка времени в прошлом) |
| `invalidjson` | битый JSON — сообщение нельзя прочитать |

Неизвестный тег (внешний/будущий) — строка легенды = имя тега как есть
(без выдумывания).

## 6. HTML-маркеры

- recall 100% в строке дефекта — зелёный; `Caught < TotalDefects` — красный;
- precision < 100% — жёлтый (с пояснением из §4.4, если оoo/fp>0);
- DLQ «совпадает» — зелёный; «РАСХОЖДЕНИЕ» — красный (класс `mismatch`
  сохраняется для обратной совместимости ссылок);
- вердикт — цветной banner (зелёный/красный).
- Инлайн CSS, без JS, самодостаточный файл (как сейчас).

## 7. Ошибки и края

- `LoadJSON` — без изменений.
- Проценты: `X%` — одна цифра после точки (текущий формат), recall/precision
  из `Overall`/`TagMetric` как есть.
- `TotalDefects == 0` для тега — строка рисуется, вердикт-правило §3.1 её
  пропускает.
- Локализация: весь новый пользовательский текст — русский; `text`/JSON
  остаются английскими (решение пользователя).
- HTML-экранирование путей/значений — по-прежнему отсутствует (pre-existing
  follow-up, не ухудшаем; не расширяем scope).

## 8. Тесты (TDD)

- `explain_test.go`: `Verdict` — healthy / recall-проблема / DLQ-mismatch /
  warnings / `DLQTopic==nil` не ошибка; группировка кластеров (разрыв >60с,
  граница 60с, пустой); легенда (все 6 тегов + неизвестный тег).
- `render_test.go` (md): вердикт-заголовок healthy и problems; секции в
  порядке §4; строка метрик с числами; легенда в таблице; ooo-пояснение
  при fp>0 и отсутствие при fp==0; DLQ: совпадение / расхождение /
  `DLQTopic==nil`; таймлайн: кластер + пометка разрыва; пустой таймлайн →
  секции нет; подвал с inputs.
- `render_test.go` (html): то же самое (ключевые маркеры: banner вердикта,
  классы цветов, полосы таймлайна).
- Существующие тесты `text`/JSON — без изменений, остаются зелёными.

## 9. Риски

- Объём статического русского текста в коде — вынесен в `explain.go`
  (const-мапы/функции), render.go остаётся структурным.
- «Легенда не совпадает с фактической семантикой проверки» — текст легенды
  сверен с README-таблицей «Проверки (6 тегов)»; при добавлении новых
  проверок легенду дополнять (не блокирует).
